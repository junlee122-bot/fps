# JOSEON-CQB — P0 보고

조선 후기 목조 건축 공간의 현대 화기 총격전. **벽이 엄폐물이 아니다** —
창호지·창살·판벽·흙벽·기와가 각기 다른 관통 등급을 가지며 화강암만이 완전 차단재다.

이 문서는 마스터 프롬프트 §8 형식의 **P0 종료 보고**다. 모든 수치는 계측 출력에서 왔다
(`tmp/gate/*.json`은 로컬 생성물 — 재현 명령을 각 절에 병기).

- 계약: `ARCHITECTURE.md` / `HARNESS.md` / `src/core/surfaces.js`(동결)
- 계약 모호·충돌 열거와 채택 해석: `docs/CONTRACT-NOTES.md` (착수 전 작성, 감사 후 2건 증보)

```bash
npm install
npm run serve          # 브라우저에서 접속. 클릭 → 포인터록, WASD/Shift/Space/Ctrl
node tools/playtest.mjs
node tools/baseline.mjs --out baseline --dpr 2
```

## 2. 하네스 — 6개 툴과 각각이 잡아낸 실제 문제

전부 P0에서, 게임 코드와 같은 커밋 안에서 구축했다.

| 툴 | 잡아낸 실제 문제 |
|---|---|
| `playtest.mjs` | **이동 모델 평형점 결함**: 질주가 5.0m/s에서 멈춤(마찰-가속 평형 5.09 < 목표 6.7). 지수 접근 모델로 교체 후 실측 6.6m/s. 또한 x=0 직선 동선이 석등(0,16)에 정확히 막히며 충돌 배선을 실증(테스트 동선을 x≈-4.6으로 이동) |
| `baseline.mjs` | **`hanji_pierced` 샷에서 결정적 스크린샷 교착**: Playwright `page.screenshot`의 "안정화 대기"가 lockstep 페이지의 컴포지터 상태와 충돌해 2회 연속 같은 샷에서 30s 타임아웃. CDP `Page.captureScreenshot` 직접 호출로 교체(158ms) |
| `imagediff.mjs` | (감사에서) **문서화된 공백 인자 형식(`--tolerance 0`)이 조용히 tolerance=1로 실행** — ±1 LSB 이동이 전부 통과하는 게이트 약화. 파서 교체 + 값 검증으로 수정, 수정 자체의 픽셀 중립성을 이 툴로 재증명 |
| `profile.mjs` | **히치 귀속 인덱스 오프바이원**: `frameTimes[i]`(레코드 i↔i+1 간격)와 프로그램 카운트 차분의 정렬 오류 — 귀속이 이 툴의 존재 이유라 치명적. 수정. 이후 실측으로 "플레이 중 셰이더 컴파일 0" 확인(프리웜 유효성 입증) |
| `capture.mjs` | 그레이박스 구도·조명 육안 확인 경로 (초기 샷 앵글 조정에 사용) |
| `shotset.mjs` | 재현성 없음이 정의인 리뷰 전용 — 게이트 사용 금지를 코드 주석·보고서에 명시 |

**결정성 감사(자동)**: `performance.now`는 `core/clock.js` 내부에만(전 소스 grep), `Math.random` 0건,
rAF 타임스탬프는 메인 루프→clock 경유만.

## 3. 성능 표

P0는 최적화 전 상태 하나뿐이므로 "전/후"가 아니라 **P0 실측**을 기록한다.
(최적화 전/후 비교는 P5 보고의 몫.)

**측정 환경 주의 (CONTRACT-NOTES B5):** 본 개발 컨테이너에는 GPU가 없어
SwiftShader(소프트웨어 렌더러, Vulkan/Subzero)로 측정했다. 절대 fps는 목표 판정에
쓸 수 없고, 이 환경에서 유효한 게이트는 **재현성·회귀·셰이더 컴파일 0·부팅**이다.
§6 fps 목표(p50 ≥ 45)는 목표 하드웨어(Apple Silicon)에서 재측정해야 한다.

`node tools/profile.mjs --duration 30 --dpr 2 --runs 3` (1512×982 @DPR2 = 5.94MP, 이동·점프 스크립트 재생):

| 지표 | P0 실측 (SwiftShader) | §6 목표 (실 GPU 기준) |
|---|---|---|
| fps p50 (중앙값 of 3 runs) | 1.8 | ≥ 45 — **이 환경에서 판정 불가** |
| fps p99 | 0.7 | ≥ 25 — 동상 |
| 최악 프레임 | 2,964 ms | ≤ 50 ms — 동상 |
| **플레이 중 셰이더 컴파일** | **0** (3 runs 전부) | **0 — 달성** |
| **부팅 (ready까지)** | **331 ms** (중앙값; DPR1 fixed 모드 604ms) | ≤ 4 s — **달성** |
| 삼각형 | 3,508 (전 샷 ≤ 6M) | ≤ 6M — **달성** |
| WebGL 프로그램 | 4 (전부 프리웜에서 컴파일, ~400ms) | — |

**P0 종료 조건 3종 (전부 통과):**

| 게이트 | 결과 |
|---|---|
| `baseline.mjs` 11샷 2회 연속 비트 동일 (DPR 2) | **통과** — `imagediff` identical:true, exit 0. (DPR 1에서도 별도 2회 비트 동일 확인) |
| `playtest.mjs` | **통과** — 31체크 (NaN·침투·무한낙하 0, 이동/충돌/점프/앉기/강체 안착 검증) |
| `profile.mjs` p50/p95/p99 + 프레임당 프로그램 카운트 출력 | **통과** — 히치 귀속(신규 프로그램 수·드로우콜·삼각형·직전 이벤트) 포함 |

## 4. 정직한 평가

- **fps 목표는 검증되지 않았다.** 이 환경(소프트웨어 GPU)에서 절대 성능은 원리적으로
  측정 불가라 §6의 p50≥45는 미확인 상태다. 근본 원인(하드웨어 부재)은 알지만 이
  환경에서는 고칠 수 없다 — 목표 하드웨어에서 `profile.mjs`를 그대로 실행하면 된다.
- **profile의 통계 품질이 이 환경에서 낮다.** 30초 벽시계에 ~50 프레임밖에 수집되지
  않아(0.5~2fps) p99가 사실상 최악값과 같다. 히치 카운트 900은 "모든 프레임이 50ms
  초과"라는 뜻으로, 소프트웨어 렌더의 상수 특성이지 스톨이 아니다(신규 프로그램 0으로 귀속 확인).
- **사격 스모크는 아직 없다.** playtest 계약의 "이동·사격" 중 사격은 무기가 생기는
  P2에서 추가된다. 현재는 이동 계열만 검증한다.
- **`viewmodel_ads` 샷은 카메라 포즈만 존재한다.** 뷰모델이 없으므로 P2 전까지
  "20배 조도" 함정 감시는 개점휴업 상태다. 샷 자체는 P0부터 게이트에 포함해 뒀다.
- **그레이박스의 육안 품질은 목표가 아니었고 실제로 낮다.** 하늘색이 단색이라 정오
  샷이 밤처럼 읽히고, 회랑 지붕 하면이 완전히 검다. P3(sky·머티리얼·톤매핑) 전까지
  의도된 상태다 — §6 비평가 루프는 P1 종료부터 돌리는 것이 유의미하다.
- **컨테이너 일시중지가 백그라운드 계측을 죽인다.** 게이트 체인이 한 번 vm fork로
  중살됐다(exit 144). 재실행으로 해결했지만, 장시간 계측은 분할 실행이 안전하다.
- **감사가 부분 실패했다.** 독립 감사 팬아웃 10에이전트 중 8이 세션 사용 한도에
  걸렸다. 완료된 2렌즈(계약 준수·물리 이식)의 발견 5건은 전부 수기 검증 후 수정했지만,
  결정성·하네스 수치·게임플레이 렌즈는 파인더가 완주하지 못해 **커버리지 공백**이
  남아 있다(발견 티저 2건은 실패 목록에서 역추적해 수정). P1 착수 전 재실행 권장.

## 5. 프로세스 노트

- **순차 단일 오너로 진행했다** (§4.1 준수). 병렬화는 읽기 전용 감사 팬아웃 1회뿐
  (결합되지 않은 관심사 — 코드 수정 없음). P0 안에서 병렬 대 순차의 신규 실측 비교는
  없다 — 비교 데이터는 참조 레포의 것(+0.46/결함 증가 vs +1.00/66→26)을 그대로 신뢰했다.
- **참조 레포(Claude of Duty)에서 직접 이식한 것**: `src/physics/math.js`(그대로),
  `bvh.js`·`character.js`·`rigidbody.js`(표면 매핑만 동결 계약 어댑터로 교체),
  lockstep 캡처 기법(페이지 자체 루프 없음), 프리웜의 "실프레임 렌더 필요" 지식,
  툴 CLI 구조. **이식 충실도는 토큰 단위 diff 감사로 검증** — 의미 변화 1건 발견
  (기본 표면 인덱스 0이 'concrete'→'HANJI'로 뒤바뀌는 잠복 결함) 후 수정.
- **측정을 무효화시킬 뻔한 발견들**:
  1. `page.screenshot`의 안정화 휴리스틱이 lockstep 페이지와 교착 — 캡처 자체가
     게이트를 못 돌게 만들었다. CDP 직접 캡처로 우회.
  2. 문서화된 CLI 형식(공백 구분)이 미지원이라 **계약 문서의 명령을 그대로 치면
     profile이 1초/1회/DPR1로 조용히 성공 출력**했다 — 성능 판정 전체가 무효가 되는
     경로. 파서를 계약 형식에 맞추고 실행으로 재검증.
  3. 히치 귀속의 오프바이원 — "어느 프레임에서 컴파일이 일어났나"가 한 프레임씩
     밀려 있었다. 지연 컴파일 스톨 사냥이 목적인 툴이라 즉시 수정.
- **수정의 픽셀 중립성은 주장이 아니라 게이트로 확인한다**: 감사 수정 5건 적용 후
  `baseline.mjs` 재캡처 → 수정 전 baseline과 `imagediff` 비교. (결과는 이 README를
  갱신하는 후속 커밋에 기록 — 측정 완료 전에 결론을 쓰지 않는다.)
- **계약 위반을 계약으로 잡았다**: world→physics 직접 import(ARCHITECTURE §3 위반)를
  감사가 발견, 주입 파사드(`physics.layers`, 표면 이름 문자열)로 교체.
