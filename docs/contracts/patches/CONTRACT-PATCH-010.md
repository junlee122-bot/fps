## PATCH-010-A — 캐릭터 기하·애니메이션 에셋 허용 (계약 개정)

### 원 계약
> 프롬프트 §2 절대 제약 1 — **아트 에셋 0개.** 이미지 파일, 3D 모델, HDRI,
> 오디오 파일, 폰트 파일을 리포지토리에 추가하지 마라.

### 개정 사유
개정된 게임(`P4-BRIEF` §0)은 캐릭터와 애니메이션을 요구한다.
절차적 생성이 가장 약한 영역이 정확히 그것이고, 히어로형 PvP는 그 영역에서 살고 죽는다.

**에셋 0개는 참조 레포를 따른 자기 제약이며, 게임이 요구한 것이 아니다.**
그리고 그 레포가 5.05/10에서 멈춘 원인으로 스스로 지목한 제약이기도 하다.

### 개정

> **캐릭터의 기하와 애니메이션에 한해 외부 에셋을 허용한다.**
>
> 허용: 스킨드 메시, 스켈레톤/리그, 애니메이션 클립
> (이동 · 사격 · 재장전 · 가젯 · 피격 · 사망)
>
> **그 외 전부는 절차적 생성을 유지한다** — 건축, 머티리얼, 하늘, FX, 오디오, 무기.

런타임 의존성은 `three` 단독을 유지한다. `GLTFLoader`는 three의 예제 모듈이므로 허용.

## PATCH-010-B — 경계: 형태와 움직임만, 색과 재질은 우리 것

> **가져오는 것은 기하와 모션이다. 머티리얼은 가져오지 않는다.**
>
> 임포트한 메시는 우리 머티리얼 시스템으로 셰이딩한다.
> 에셋에 딸려온 알베도 · 노멀 · 러프니스 텍스처를 그대로 쓰지 마라.

### 근거
1. **팔레트 규율이 룩을 지탱하는 유일한 장치다.** 단청 5색 + 목재/흙 중성색.
   외부 텍스처를 그대로 쓰면 `paletteaudit`이 깨지고, 그것을 면제하면 규율이 무너진다
2. 캐릭터가 건축과 **다른 세계에서 온 것처럼** 보이면 스타일라이즈드 선택이 무효가 된다
3. 약점이었던 것은 **기하와 애니메이션**이지 머티리얼이 아니다.
   필요한 것만 가져오고 나머지는 지킨다

### 요구
- 임포트 메시는 `src/materials`의 프로파일로 셰이딩
- `paletteaudit` 한도 1.5%를 **캐릭터 포함 상태에서** 유지
- 임포트 텍스처를 쓰려면 **팔레트 대역으로 재매핑한 뒤** 절차 텍스처와 동일 취급

## PATCH-010-C — 파급 점검

`PATCH-004-D`(게이트 노후화) 적용 대상이다. **새 실패 모드를 기존 게이트가 보는가.**

| 게이트 | 영향 | 요구 |
|---|---|---|
| `paletteaudit` | 캐릭터 색이 밴드 밖일 수 있음 | 캐릭터 포함 재측정. 한도 유지 |
| `silhouetteaudit` | **여전히 적용.** 오히려 더 중요 | 임포트 캐릭터도 6쌍 2축 이상 상이 |
| `determinismaudit` | 애니메이션 재생이 벽시계를 읽을 수 있음 | 스키닝·클립 시간 전부 `core/clock.js` |
| `baseline` | 에셋 로드 완료 전 캡처 위험 | `ready`에 에셋 로드 포함. 2회 비트 동일 |
| `profile` | 삼각형 급증 | §아래 예산 참조 |
| `surfaceaudit` | 캐릭터 메시의 표면 타입 미매핑 | 캐릭터에도 기본값 금지(`PATCH-001-D`) 적용 |

### 삼각형 예산 개정
현재 `tris_scene` 135,274. 캐릭터 4종이 얹힌다.

| 지표 | 기존 | 개정 |
|---|---|---|
| `tris_scene` | ≤ 600,000 | **≤ 600,000 유지** |
| 캐릭터 1종당 | — | **≤ 25,000** (4종 합 100 k) |
| `tris_frame_p95` | ≤ 250,000 | ≤ 250,000 유지 |

캐릭터가 25 k를 넘으면 **감면(decimate)하라.** 예산을 올리지 마라.
실루엣으로 읽히는 게임이므로 고밀도 메시의 가치가 낮다.

### 부팅
에셋 로드가 `boot_cpu`에 추가된다. 게이트 3 s 유지.
초과하면 **메시를 줄여라.** 프리웜을 줄이지 마라(`PATCH-005-E` 우선순위 불변).

### 라이선스
외부 에셋의 라이선스를 `docs/ASSET-LICENSES.md`에 **에셋별로** 기록하라.
출처 · 라이선스 · 상업적 사용 가부. 출처 불명 에셋은 쓰지 마라.

## PATCH-010-D — 성능 실측 플랫폼 개정

### 문제
`PATCH-005-H`가 **Apple Silicon**을 지정했다. 이는 참조 레포의 측정 기계를 그대로 옮긴 것이며,
근거가 없다. 발주자에게 해당 기계가 없다.

### 개정
> **필요한 것은 특정 플랫폼이 아니라 "SwiftShader가 아닌 실제 GPU"다.**
> Windows · Linux · macOS 무관. 외장·내장 GPU 무관.

`profile.mjs`가 이미 소프트웨어 렌더러를 감지해 `GPU-INVALID` 배너를 출력한다.
그 배너가 **뜨지 않으면** 유효한 측정이다.

### 에이전트 요구 사항
발주자가 Windows에서 실행할 수 있도록 준비하라.

1. `profile.mjs`가 Windows에서 동작하는지 확인하고, 필요한 Chromium 플래그를 추가하라
   (헤드리스 GPU가 불안정하면 **헤드풀 실행 경로**를 제공하라)
2. 실행 결과에 **GPU 식별자**(`UNMASKED_RENDERER_WEBGL`)와 해상도 · DPR을 기록하게 하라.
   플랫폼 간 절대 비교가 목적이 아니라 **자기 자신과의 시계열 비교**가 목적이다
3. `docs/PROFILE-RUN.md`에 Windows 실행 절차를 적어라 —
   node 설치부터 결과 JSON까지, 발주자가 그대로 따라 할 수 있게
4. 선택: 정적 빌드를 배포해 **눈으로 확인하는 경로**도 함께 제공하라.
   히치 귀속은 없지만 체감 fps와 룩을 즉시 볼 수 있다

### 회신 항목 (변경 없음)
`gpuDependent.fps_p50_median` / `fps_p99_median` / `frame_worst_max` /
`bootCpu` / `bootGpu` / `leadingIndicators.cpuFrameMsP95` /
`horizonReadbacksDuringPlay`(0이어야 함) / GPU 식별자

## 2. 기록

에셋 0개 제약은 **참조 레포에서 빌려온 것이지 이 게임이 요구한 것이 아니었다.**
그 레포는 같은 제약으로 근거리 머티리얼의 한계에 부딪혔고, 우리는 그것을
비목표로 선언해 회피했다(`프롬프트 §3` — 스타일라이즈드는 타협이 아니라 선택).

캐릭터는 다르다. **회피할 방법이 없다** — PvP 히어로형 게임에서 캐릭터와 애니메이션은
비목표로 선언할 수 있는 항목이 아니다. 그래서 제약을 푼다.

단 `PATCH-010-B`가 그 해제를 **가장 좁은 범위로** 가둔다.
기하와 모션만 가져오고, 색과 재질은 지킨다.
