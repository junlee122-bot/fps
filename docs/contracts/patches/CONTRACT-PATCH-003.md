## 0. 증명 독립 검증

`S ≡ Σ tᵢ(1+dᵢ)(−ln retainᵢ)` 로 두면 `R = exp(−S/k)`.

DMR 요구:
- `TILE + 보토` 관통(여유 포함) → `S_TB / k ≤ −ln(0.1875) = 1.674`
- `EARTH_WALL 100mm` 부분(여유 포함) → `S_E / k ≥ −ln(0.12) = 2.120`

두 식에서 `k`를 소거하면 **`S_E / S_TB ≥ 1.2664`**.

보토가 `EARTH_WALL` 상수를 공유할 때, `L ≡ −ln retain_E > 0`에 대해

```
S_E / S_TB = 18L / (2.375 + 14.4L)
```

이 함수는 `L`에 대해 단조증가하며 **상한 18/14.4 = 1.25**.
`1.25 < 1.2664`이므로 해가 존재하지 않는다. 상한 자체도 `retain_E → 0`이라는
퇴화 극한에서만 접근한다.

**보고된 증명이 옳다.**

## PATCH-003-A — `ROOF_SOIL` 신설 (승인)

### 승인 근거
보토(알매흙)는 산자 위에 얹는 지붕 흙층이고, 심벽은 외(椳) 사이에 다져 넣고
마감한 벽체 충전재다. 밀도·결속·시공 방식이 다른 별개 재료다.

P1에서 두 재료를 한 태그로 묶은 것은 편의상 선택이었으며
(`CONTRACT-NOTES P1-2`에 기록), 물리적 사실이 아니었다.

> **본 승인은 표면 신설이 아니라 잘못된 병합의 정정이다.**

## PATCH-003-B — 표면 신설 기준 (신규, 영구 조항)

표면을 하나 늘릴 때마다 자유 파라미터가 하나 늘어난다.
충분히 늘리면 어떤 결과 표든 만족 가능해지고, 그 순간 표는 제약으로서 의미를 잃는다.

> **`ARCHITECTURE.md` §2에 추가한다.**
>
> 신규 표면은 아래 **3개를 전부** 통과해야 승인된다.
>
> 1. **물리적 구별** — 기존 표면과 재료·밀도·시공이 실제로 다를 것
> 2. **독립적 정당화** — 지금 풀려는 수치 문제와 **무관하게** 존재 근거가 설 것.
>    "이 표면이 없으면 표가 안 풀린다"는 근거가 되지 않는다
> 3. **플레이어 구별 가능성** — `fx`와 `audio` 프로파일이 기존 표면과 다를 것.
>    관측 불가능한 표면은 새 재료가 아니라 자유변수다
>
> 3번이 가장 중요하다. 이 조건을 통과하지 못하는 제안은 반려한다.

`ROOF_SOIL`은 3개를 전부 통과한다.

## PATCH-003-E — 실행가능성 선증명 (신규, 프로세스 조항)

### 사유
블로커 2건이 연속 발생했고 **둘 다 계약 결함**이다.
근본 원인은 동일하다 — 결과 표 30칸을 **동시 만족 가능한지 검증하지 않고**
계약으로 동결했다.

이번 패스에서 에이전트가 구현 착수 전에 실행가능성부터 증명한 것이 옳은 대응이었다.
이를 규칙으로 승격한다.

> **프롬프트 §4에 추가한다.**
>
> 계약이 **결과 표·매트릭스·수치 목표**를 규정하는 경우,
> 해당 패스의 **첫 작업은 구현이 아니라 실행가능성 증명**이다.
>
> 1. 자유 지렛대를 명시적으로 열거한다
> 2. 요구 조건을 지렛대에 대한 부등식계로 환원한다
> 3. 해집합이 비어 있지 않음을 보인다
> 4. 공집합이면 **즉시 멈추고** 증명과 최소 해제안을 함께 보고한다
>
> 실행가능성이 확인되기 전에 그 표에 의존하는 코드를 작성하지 마라.
> 구현을 진행한 뒤 표를 맞추지 못해 상수를 조정하는 것은 이 순서의 역이며 금지한다.
