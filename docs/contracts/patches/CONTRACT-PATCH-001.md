# CONTRACT-PATCH-001

**적용 대상:** `ARCHITECTURE.md`, `HARNESS.md`
**사유:** P0 독립 감사 및 `docs/CONTRACT-NOTES.md`가 제기한 모순 중 3건은
구현이 아니라 **계약 문서의 결함**이다. 아래 정정이 원문을 대체한다.
**적용 시점:** P1 착수 전.

---

## PATCH-001-A — "화강암 유일"의 범위 오류

### 문제
`ARCHITECTURE.md` §2가 `GRANITE`를 "유일한 신뢰 엄폐물"이라 서술하지만,
`surfaces.js`의 `PenClass.BLOCK`은 `GRANITE`, `BRONZE`, `PACKED_DIRT` 3종이다.
`COVER_SURFACES`가 3개를 반환하므로 AI 엄폐 선택과 레벨 검증이 문서와 어긋난다.

### 판정
**코드가 맞고 산문이 틀렸다.** 세 표면 모두 물리적으로 탄환을 정지시키는 것이 옳다.
설계 의도는 "BLOCK이 하나뿐"이 아니라 **"수직 건축재 중 엄폐 가능한 것은 화강암뿐"**이었다.

- `PACKED_DIRT` — 지면. 수평면이므로 엄폐물이 될 수 없다. BLOCK이지만 엄폐 후보 아님.
- `BRONZE` — 범종·솥 등 희소 프롭. 엄폐 가능하지만 **맵당 3개 이하로 배치 제한**한다.
  의도된 희소 자원이지 일반 엄폐물이 아니다.

### 정정문 (§2 비고란 및 §5 설계 규칙을 대체)

> 완전 차단 표면은 `GRANITE`, `BRONZE`, `PACKED_DIRT` 3종이다.
> 이 중 **엄폐물로 기능하는 수직 건축재는 `GRANITE`가 유일하다.**
> `PACKED_DIRT`는 지면이므로 엄폐 후보에서 제외한다.
> `BRONZE`는 의도적 희소 자원이며 맵당 3개 이하로 배치한다.

### 코드 변경 요구
`surfaces.js`에 아래를 추가한다. **기존 항목은 수정하지 않는다.**

```js
/** 수직 엄폐물로 기능하는 표면 — 레벨 검증·AI 엄폐 선택의 기준 */
export const VERTICAL_COVER_SURFACES = Object.freeze(['GRANITE', 'BRONZE']);

/** 맵당 배치 상한. 초과 시 레벨 검증 실패 */
export const COVER_PLACEMENT_LIMITS = Object.freeze({ BRONZE: 3 });
```

`COVER_SURFACES`는 물리 질의용으로 유지한다.
**AI 엄폐 선택과 §5 레벨 규칙 검증은 `VERTICAL_COVER_SURFACES`를 사용한다.**

## PATCH-001-B — 잔여속도 표의 지위 오류

### 문제
`ARCHITECTURE.md` §2의 "잔여속도" 열이 관측 가능한 결과처럼 서술되어 있으나,
`computePenetration()`은 두께와 밀도를 지수로 적용한다.

예: `WOOD_COLUMN` 1cm 통과 시 실효두께 = 1 × (1 + 0.65) = 1.65,
잔여 = 0.35^1.65 ≈ **0.185**. 표의 35%와 일치하지 않는다.
표가 일치하는 것은 `density = 0`인 경우뿐이다.

### 판정
**코드가 규범이고 표는 파라미터다.** 표의 값은 예측 결과가 아니라
`energyRetain` **상수 자체**이며, 두께·밀도가 적용되기 전의 입력값이다.

### 정정문 (§2 열 제목 및 표 서문을 대체)

> 열 제목 `잔여속도` → **`energyRetain (파라미터)`**
>
> 이 열은 관측되는 잔여 에너지가 아니라 `surfaces.js`의 상수 입력값이다.
> 실제 잔여 에너지는 두께와 밀도가 지수로 적용된 결과이며,
> **유일한 규범적 정의는 `computePenetration()`의 출력이다.**
> 게임플레이 밸런스 논의는 이 표가 아니라 함수 출력을 근거로 한다.

### P2 유닛 테스트 요구
표를 기대값으로 쓰는 테스트를 작성하지 마라. 테스트는 다음을 검증한다:

1. `BLOCK` 3종은 두께와 무관하게 `residual === 0`, `stoppedAt` 설정
2. `DECAL` 2종은 `path`에 나타나지 않고 에너지에 영향 없음
3. 다층 순서 의존성: `HANJI → WOOD_LATTICE`와 역순의 잔여값이 다름
4. 4레이어 시나리오(창호지→창살→실내공기 없음→반대편 창호지)에서 관통 성립
5. 단조성: 임의 표면에서 두께 증가 시 잔여 에너지가 **엄격히 감소**
6. 2% 임계값 경계에서 `stoppedAt`이 올바른 레이어를 가리킴

## PATCH-001-C — HARNESS §4 CLI 예시의 조용한 오측정

### 문제
`HARNESS.md` §4의 `profile.mjs` 예시를 문자 그대로 실행하면 기본값이 적용되어
1초 / 1회 / DPR 1로 측정된다. 이는 §6이 규정한 측정 조건
(30초 이상, 3회, DPR 2)과 다르며 **실패가 아니라 조용한 오측정**으로 나타난다.
계약 문서를 따른 결과가 계약 위반이 되는 상태였다.

### 판정
**문서 결함이다.** 도구 기본값이 계약 기본값과 달랐다.

### 정정문 (§4 `profile.mjs` 항목을 대체)

> ```
> node tools/profile.mjs            # 계약 기본값으로 실행 = --duration 30 --runs 3 --dpr 2
> ```
>
> `profile.mjs`의 **기본값은 §6 측정 조건과 동일해야 한다.**
> 인자 없이 실행한 결과가 곧 게이트 판정에 쓰이는 수치다.
> 더 짧거나 적은 조건은 명시적 플래그로만 가능하며, 이 경우 출력 헤더에
> `NON-CONTRACT MEASUREMENT` 배너를 반드시 출력한다.

### 일반 원칙 (신규, HARNESS §0에 추가)

> **모든 하네스 툴의 기본값은 계약 조건과 일치해야 한다.**
> 인자를 잊었을 때 나오는 결과는 "덜 엄격한 통과"가 아니라 "계약 조건 그대로"여야 한다.
> 이 원칙을 어기는 툴은 결함이다.

## PATCH-001-D — 기본 표면 금지 (신규 조항)

### 사유
P0 이식 감사가 잡아낸 결함: 기본 표면 인덱스 0의 의미가
`'concrete'`(차단재)에서 `'HANJI'`(자유 관통)로 뒤집혀 있었다.
미매핑 지오메트리 전체가 조용히 관통 가능해지고 AI 엄폐 판정이 무효화되는 결함이었다.

수정은 완료됐으나, **근본 원인은 값이 아니라 기본값의 존재 자체다.**

### 신규 조항 (`ARCHITECTURE.md` §2에 추가)

> **표면 매핑에 기본값(fallback)을 두지 않는다.**
> 지오메트리→`SurfaceType` 어댑터는 전수 매핑이어야 하며,
> 미지의 지오메트리에 대해 조용히 값을 반환하지 말고 **throw한다.**
>
> 조용한 게임플레이 결함을 시끄러운 크래시로 바꾸는 것은 언제나 이득이다.
> 이 규칙은 `physics`, `ai`, `audio`, `fx` 네 소비자 전부에 적용된다.

### P1 검증 요구
월드 지오메트리 전체를 순회하며 표면 미매핑 노드를 검출하는
`tools/surfaceaudit.mjs`를 P1에서 추가한다. 미매핑 1건이라도 있으면 exit 1.

## 적용 확인

패치 적용 후 아래를 재실행하여 픽셀 중립성을 확인한다.
`VERTICAL_COVER_SURFACES` 추가는 순수 신규 export이므로 렌더 결과가 변하지 않아야 한다.

```bash
node tools/baseline.mjs --out current/
node tools/imagediff.mjs baseline/ current/    # identical:true 여야 함
```

`identical:false`가 나오면 패치 적용 과정에서 의도치 않은 변경이 섞인 것이다.
차분 이미지를 확인하고 원인을 제거한 뒤 재실행하라.
