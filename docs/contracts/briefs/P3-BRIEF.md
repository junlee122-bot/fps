# P3-BRIEF — 머티리얼 · 하늘 · 렌더 · 톤매핑

**전제:** P2B 종료 게이트 전부 통과. HEAD `44222b2`.
**이 패스의 한 줄:** 이 프로젝트가 성공하거나 실패하는 지점.

---

## 0. 이 패스가 다른 이유

P0~P2B는 합격/불합격이 수치로 떨어졌다. 비트 동일이거나 아니거나,
30칸이 맞거나 아니거나, exit 0이거나 1이었다.

**P3의 판정 기준은 "이 프레임이 의도된 스타일라이즈드로 읽히는가"다.**
이것은 주관적이고, 따라서 **통과했다고 주장하기 가장 쉬운 패스**다.

참조 레포가 10점 만점에 5.05에서 멈춘 지점이 여기다. 실패 양식은 두 가지였다.

1. **결합계를 나눴다.** 병렬 3라운드가 점수 +0.46에 결함 60 → 47 → **66 (증가)**.
   단일 오너 순차 1패스가 +1.00에 결함 66 → **26**.
2. **포토리얼을 향했다.** 절차적 텍스처가 근거리에서 사진이 아니라 노이즈로 읽혔고,
   비평에 대응해 알베도를 계속 깎아 가장 오래 보는 물체의 재질 분리를 영구히 망쳤다.

이 브리프의 목적은 두 실패를 **절차로 막는 것**이다.

## 1. 분할 금지

> **P3는 하나의 패스이며 하나의 오너가 소유한다.**

P2를 A/B로 나눈 것이 성공했으므로 P3도 나누고 싶어질 것이다. **반대로 가는 판단이다.**

- `weapons`와 `fx`는 `ballistic:*` 이벤트로 **분리 가능한 관심사**였다.
- `materials` · `sky` · `render` · 톤매핑은 **분리 불가능한 결합계**다.
  톤매핑을 바꾸면 머티리얼의 정답이 바뀌고, 하늘을 바꾸면 노출이 바뀌고,
  노출을 바꾸면 알베도의 정답이 바뀐다.

내부에 순서와 체크포인트를 두되(§3), **패스 경계로 나누지 마라.**
병렬 에이전트에 이 4개를 동시 할당하는 것은 금지다.

## 2. 선결 조건

적대 감사 워크플로가 **세 번 연속 세션 한도로 중단**됐다 (P0 8/10, P2B 3/5).
지금까지는 직접 검토로 갈음할 수 있었다. **P3에서는 불가능하다.**
비평이 P3의 유일한 최종 판정 수단이기 때문이다.

### 2-1. 세션 한도 내성 설계

- **비평가 1명 = 세션 1개.** 절대 병렬 실행하지 마라
- 각 비평가는 판정을 **즉시 파일로 기록**한다:
  `docs/critique/R{라운드}-S{샷번호}.md`
- 중단되면 마지막 완료 파일 다음부터 재개한다. **진행분을 잃지 않는다**
- 11샷 × 라운드. 한 라운드가 며칠 걸려도 무방하다

### 2-2. 비평가는 증상만 보고한다

참조 레포에서 비평가들은 3라운드 동안 무기가 "텍스처가 없다"고 보고했다.
실제 원인은 반대였다 — 스페큘러 지배 상태에서 디퓨즈가 L=26까지 눌려 있었고,
이전 라운드들이 "너무 밝다"는 불만에 알베도를 계속 깎은 결과였다.

> **비평가는 무엇이 잘못 보이는지 열거한다. 원인을 진단하거나 수정안을 제시하지 않는다.**
> 진단은 오너가 한다. 비평가의 진단을 그대로 실행하면 참조 레포의 경로를 반복한다.

### 2-3. 비평가 지시문

각 비평가에게 정확히 이것만 준다. **브리프도, 다른 샷도, 의도도 주지 마라.**

```
이 이미지 하나를 평가하라. 다른 이미지나 프로젝트 의도는 주어지지 않는다.

1. 이 프레임은 "의도된 스타일"로 읽히는가, "미완성"으로 읽히는가. 하나를 골라라.
2. 프레임을 망치는 결함을 전부 열거하라. 각 항목은 관측 가능한 서술이어야 한다.
   ("먼지 텍스처가 필요하다" ✗ / "기둥과 벽의 밝기가 구별되지 않는다" ✓)
3. 결함 개수를 명시하라.
4. 10점 만점 점수.

원인을 추측하지 말고, 수정 방법을 제안하지 마라.
```

### 2-4. 판정 규칙

- **결함 총 개수가 주 지표다. 점수는 보조 지표다.**
- 점수가 올라도 결함이 늘면 **그 라운드는 실패**다.
  참조 레포의 병렬 라운드가 정확히 이 형태였다
- "미완성"으로 읽힌 샷이 11개 중 3개를 초과하면 라운드 실패
- 결함을 **결합 관심사별로 묶고**, 각 묶음에 단일 오너를 배정해 순차 수정

### 2-5. 선결 — `chainaudit` 경로 대표성

P2B가 잡은 셸 와인딩 반전 결함은 **P1.5부터 존재했고 `chainaudit` 9경로를
전부 통과했다.** 9경로에 거울 대칭면이 하나도 포함되지 않았기 때문이다.

**툴의 결함이 아니라 경로 선정의 결함이다.** 게이트가 통과했다는 사실이
그 게이트가 대표성을 가진다는 뜻이 아니다.

추가할 경로: 합각면, 객사 북경사, 추녀 교차부, 대칭 배치된 회랑 양단.
보강 후 `9/9`가 아니라 **`N/N`**으로 보고하라.

### 2-6. 선결 — `overdraw_estimate` 지표 검증

P2B 실측 0.003 / 예산 2.5는 **지표가 안전하다는 신호가 아니라
시험되지 않았다는 신호**다. 최악 시나리오에서 파티클이 288개(예산 4,000)에 그쳤다.

삼각형 예산이 P1에서 5.6%만 사용된 것과 같은 상태다.

합성 고부하 케이스(파티클 3,500개 강제 방출)를 만들어 지표가 예산 근처까지
**선형으로 반응하는지** 확인하라. 반응하지 않으면 산출식이 틀린 것이며,
§8의 안개·반투과 편입 전에 먼저 고쳐야 한다.

## 4. 신규 게이트: `tools/paletteaudit.mjs`

팔레트 규율은 이 프로젝트에서 **절차적 생성의 약점을 감추는 주 수단**이다.
산문 규칙으로 두면 지켜지지 않는다. 수치 게이트로 바꾼다.

### 허용 색역
11샷 전 픽셀을 HSV로 변환하여 검사한다.

| 계열 | 색상(hue) | 비고 |
|---|---|---|
| 청 + 하늘 | 175° – 240° | 단청 청록과 천공을 함께 포함 |
| 적 | 355° – 15° | |
| 황 | 40° – 60° | |
| 목재 · 흙 | 20° – 40° | 채도 ≤ 0.35 |
| 백 · 흑 (중성) | 임의 | 채도 < 0.10 |

### 판정
- 채도 ≥ 0.10인 픽셀은 위 색상 대역 중 하나에 속해야 한다
- 위반 픽셀 비율이 샷당 **1.5%를 초과하면 exit 1**
  (안티에일리어싱 프린지, 스페큘러 색조를 위한 허용치)
- 샷별 위반율과 위반 픽셀의 색상 히스토그램을 출력한다

**임계값을 올려서 통과시키지 마라.** 위반이 나오면 색을 고친다.

**케이스 12** — `harnesstest`에 음성 테스트 추가:
인위로 자색(300°) 패치를 주입한 입력에서 반드시 exit 1.

## 5. 신규 게이트: `tools/albedoaudit.mjs`

참조 레포가 **근본 원인을 알았으나 고치지 못했다**고 기록한 유일한 항목이
알베도 위조다. 우리는 P2A에서 뷰모델 리그를 구조적으로 정직하게 만들었다.
P3는 그것을 깨뜨릴 수 있는 유일한 패스다.

### 5-1. 휘도 정합
알베도가 알려진 카드 3장(0.04 / 0.18 / 0.90)을 월드에 배치하고 렌더한다.

- `L(0.18) / L(0.04)` ≈ 4.5 (±15%)
- `L(0.90) / L(0.18)` ≈ 5.0 (±15%)
- 벗어나면 exit 1 — 렌더 파이프라인이 알베도를 선형적으로 다루지 않는다는 뜻

### 5-2. 알베도 매니페스트
`src/materials/albedo-manifest.json`에 **의도한 물리 알베도**를 선언한다.

```json
{ "gunmetal": 0.07, "polymer": 0.12, "hanji": 0.72, "granite": 0.35, ... }
```

`albedoaudit`은 실제 머티리얼의 알베도 값을 매니페스트와 대조한다.
**편차 10% 초과 시 exit 1.**

효과: 조명을 보정하기 위해 알베도를 깎으려면 매니페스트를 고쳐야 하고,
그것은 diff에 남는다. 조용한 위조가 불가능해진다.

### 5-3. 검정 카드
알베도 0.0 카드가 배경보다 밝게 렌더되면 즉시 exit 1.
(P2A `viewmodelaudit`에서 이미 적용 중 — 월드 카드에도 확장)

**케이스 13** — `harnesstest`에 음성 테스트: 알베도를 1/3로 깎은 입력에서 exit 1.

## 6. 포토리얼 함정 — 운영적 판정

산문으로 "포토리얼을 추구하지 마라"라고 쓰는 것으로는 부족하다.
수정 방향을 판정하는 규칙을 둔다.

> 결함에 대한 수정 방향이
> - **"더 사실적으로 보이게 표면 디테일을 추가한다"** → **반려**
> - **"의도를 더 읽히게 만든다"** → **채택**

구체 예시:

| 비평 | 반려되는 수정 | 채택되는 수정 |
|---|---|---|
| 기와가 평평해 보인다 | 마모·이끼·얼룩 노이즈 추가 | 기와골 곡률의 명암 대비 강화 |
| 흙벽이 가짜 같다 | 고주파 디테일 노멀맵 | 짚 혼입의 방향성을 큰 스케일로 정리 |
| 단청이 인쇄물 같다 | 물감 번짐·마모 노이즈 | 문양 위계(머리초/연화/금문)를 명확히 분리 |

**절차적 생성이 잘하는 것은 평면적 색면, 반복 문양, 볼류메트릭이다.
못하는 것은 인물 피부와 마모된 금속이다.** 잘하는 쪽으로 밀어라.

## 7. 프리웜 · 프로그램 · 부팅

P2B가 프로그램 11개를 단일 머티리얼 + 데이터 프로파일로 억제한 것은 좋은 설계였다.
**P3는 그 억제가 시험되는 패스다.** 머티리얼 15종 × 조명·그림자 변형이 들어온다.

| 지표 | P3 예산 | 최종 상한 |
|---|---|---|
| 고유 셰이더 프로그램 | ≤ 110 | 120 |
| 부팅 | ≤ 4 s | 4 s |
| 플레이 중 셰이더 컴파일 | **0** | 0 |

- **`compileAsync`만으로는 그림자 변형이 잡히지 않는다** (P0에서 확인된 사실).
  CSM 캐스케이드별 변형을 프리웜 목록에 명시적으로 포함하라
- 부팅 4초는 P3에서 처음 실제 압박을 받는다. 528 ms에서 크게 오를 것이다.
  초과하면 프리웜을 줄이지 말고 **머티리얼 변형 수를 줄여라** —
  플레이 중 컴파일 0이 부팅 시간보다 우선한다

## 8. Overdraw

P2B 실측 0.003은 회색 규율 하의 빈약한 FX에서 나온 수치이며 **시험된 값이 아니다.**
P3에서 파티클 크기·불투명도·발광, 볼류메트릭 안개, 창호지 반투과가 들어오면
자릿수가 바뀐다.

| 지표 | P3 예산 | 최종 상한 |
|---|---|---|
| `overdraw_estimate` p95 | ≤ 3.0 | 4.0 |

볼류메트릭 안개와 `HANJI` 반투과를 `overdraw_estimate` 산출에 **포함하라.**
현재 산식은 파티클과 데칼만 센다.

측정 시나리오: `fog_wall` 샷 조건에서 실내 산탄 연사.

## 9. 지오메트리 동결

> **P3는 지오메트리를 수정하지 않는다.**

`world`는 P1/P1.5의 소유이며 P3는 소비자다.
공포 밀도나 부재 구성이 부족하다고 판단되면 **직접 고치지 말고 멈추고 보고하라.**
P1 소유로의 회귀는 별도 지시로만 가능하다.

노멀맵, 시차 폐색 매핑, 곡률 기반 에지 마모는 머티리얼이므로 허용된다.
**정점을 추가하거나 이동시키는 것은 금지다.**

`tris_scene` ≤ 600 k가 변하지 않아야 한다. 변하면 §9 위반이다.

| 3중 공면 미지원 | 지오메트리가 동결이므로 P3에서 신규 발생 불가. 한계로 유지 |
| Apple Silicon fps 실측 | **P3에서 필수.** C4 종료 시 실측 없이 P4로 넘어가지 마라 — 이 패스가 GPU 부하를 결정한다 |

## 12. 보고 형식

9. 계약 모호·충돌 신규 발견분
