# P2A-BRIEF — 무기 · 탄도 · 관통 · 창호지 투과율

**전제:** P1.5 종료 게이트 9종 통과. 커밋 `9ac078f`.
**분할 사유:** 원 계약의 P2는 무기 + 탄도 + 관통 + FX였다. 이를 둘로 나눈다.

> **P2A (이번 패스):** 무기 3종, 탄도, 다층 관통 배선, `HANJI` 동적 투과율.
> **FX는 플레이스홀더만.** 파티클·데칼·예광·총구화염 금지.
>
> **P2B (다음 패스):** GPU 파티클, 데칼, 예광, 총구화염 — 결정성 요구를 걸고.

FX는 참조 레포에서 베이스라인 재현성이 죽은 지점이다(파티클 수명·데칼 버퍼 누수).
관통 배선과 동시에 넣으면 베이스라인이 깨졌을 때 원인을 분리할 수 없다.
**P2A는 "관통이 정확하고 베이스라인이 여전히 비트 동일하다"만 증명한다.**

## 1. 설계 원칙 — 무기는 표면으로 정의된다

이 프로젝트에서 무기의 정체성은 반동·연사속도·데미지가 아니라
**어떤 표면을 이기는가**다. 무기 3종은 `surfaces.js` 표와의 관계로만 구별된다.

이것이 §2 표를 규범으로 두는 이유다.

## 2. 무기 3종 — 결과 표가 규범이다

### 2-1. 요구 결과

각 무기가 **기준 두께**(`P1-BRIEF` §2 두께표)에서 산출해야 하는 결과다.

| 표면 | 카빈 5.56 | 산탄총 12ga | 지정사수 7.62 |
|---|---|---|---|
| `HANJI` 0.3 mm | 관통 | 관통 | 관통 |
| `FABRIC` | 관통 | 관통 | 관통 |
| `WOOD_LATTICE` 24 mm | 관통 | 관통 | 관통 |
| `THATCH` | 관통 | 부분 | 관통 |
| `WOOD_PLANK` 45 mm | 관통 | **정지** | 관통 |
| `ROOF_TILE` 30 mm | 관통 | **정지** | 관통 |
| `ROOF_TILE` 30 + 보토 80 | 부분 | 정지 | 관통 |
| `WOOD_COLUMN` ø300 | **정지** | 정지 | **부분 관통** |
| `EARTH_WALL` 100 mm | **정지** | 정지 | **부분 관통** |
| `GRANITE` / `BRONZE` / `PACKED_DIRT` | 정지 | 정지 | 정지 |

정의: **관통** = 잔여 ≥ 초기의 15% / **부분** = 0% < 잔여 < 15% / **정지** = 잔여 0%

### 2-2. 전술적 정체성 (위 표에서 자동으로 도출된다)

- **카빈 5.56** — 기준 무기. 창호·창살·판벽·기와를 뚫고 기둥과 흙벽에서 멈춘다.
  실루엣 사격의 주력.
- **산탄총 12ga** — 종이와 천만 뚫는다. 대신 **다중 탄자로 넓은 면적을 한 번에 파괴**해
  창호 한 짝을 통째로 지운다. 실루엣을 쏘는 게 아니라 벽을 없애는 무기.
- **지정사수 7.62** — **유일하게 흙벽과 기둥을 이긴다.** 마당 건너 실내를 벽 너머로
  타격하는 유일한 수단. 대신 근접 기동성 페널티.

### 2-3. 에너지는 자유 파라미터

초구에너지 값은 §2-1 결과를 달성하기 위한 **튜닝 대상**이지 규범이 아니다.
출발점: 5.56 ≈ 1,800 J / 12ga 펠릿 9개 × ≈ 200 J / 7.62 ≈ 3,400 J.

`computePenetration()`의 상수는 **동결이다.** 표를 맞추기 위해
`surfaces.js`를 수정하지 마라. 에너지와 탄자 수만 조정한다.
에너지 조정으로 표를 만족시킬 수 없으면 작업을 멈추고 보고하라.

### 2-4. 산탄총 다중 탄자
펠릿 각각이 독립적으로 `computePenetration()`을 통과한다.
9발이 하나로 뭉뚱그려지면 안 된다 — 창호 파괴 면적이 이 무기의 정체성이다.

## 3. 뷰모델 조명 — 참조 레포가 영구히 망친 지점

참조 레포는 뷰모델 광원 리그가 월드 대비 **알베도당 약 20배 조도**를 전달했다.
순수 검정 재질이 배경 L=91 위에서 L=110으로 렌더됐고(F0=0.04만으로),
이를 보정하려 모든 무기 알베도를 물리값의 **1/3로 속였다.**
그 결과 게임에서 가장 오래 보는 물체의 재질 분리가 영구히 제한됐다.

**리그는 P2A에서 만들어지고 P3가 그것을 상속한다. 지금 막아야 한다.**

### 요구
> 뷰모델은 월드와 **동일한 조도 단위**를 사용한다.
> 뷰모델 전용 광원 부스트, 별도 노출, 알베도 보정 계수를 도입하지 마라.

### `tools/viewmodelaudit.mjs` (신규)
1. 알베도가 알려진 테스트 카드(예: 0.18 중성 그레이)를 **월드 공간**과
   **뷰모델 공간**에 각각 배치
2. 동일 조명 조건에서 렌더, 두 카드의 선형 휘도 측정
3. 비율이 **1.0 ± 0.10** 범위를 벗어나면 exit 1
4. 추가로 순수 검정(알베도 0.0) 카드가 배경보다 밝게 렌더되면 즉시 exit 1

**케이스 9 원칙 적용:** `harnesstest`에 `viewmodelaudit` 음성 테스트를 추가하라.
인위로 뷰모델 광원을 2배 부스트한 입력에서 반드시 exit 1이어야 한다.

## 4. 관통 배선

### 4-1. 레이 → 레이어 체인 변환
탄환 레이가 통과하는 모든 표면을 **진입 순서대로** 수집해
`computePenetration(energy, layers)`에 전달한다.

- 두께는 실제 지오메트리 진입·진출점 거리에서 산출한다. 상수를 쓰지 마라.
- `DECAL` 표면(`DANCHEONG`, `LACQUER`)은 체인에 포함하되 함수가 스킵하도록 둔다.
- **기본 표면 금지 조항(PATCH-001-D)** 적용: 미매핑 표면을 만나면 throw.

필수 성립 체인:
```
창호지 → 창살 → [실내] → 창살 → 창호지          (4레이어 관통)
기와 → 보토 → 서까래 → [실내]                   (지붕 관통)
담장상부 기와 → 관통  /  담장하부 화강암 → 정지
누각 우물마루 40 mm → 아래층으로 관통
```

### 4-2. 유닛 테스트 (`CONTRACT-PATCH-001` PATCH-001-B 6종 + 추가)
7. §2-1 결과 표 **전 칸**에 대한 무기×표면 매트릭스 검증
8. 산탄 9펠릿이 독립 계산되고 합산되지 않음
9. 두께가 지오메트리에서 산출됨 — 동일 표면을 다른 두께로 배치했을 때 결과가 다름

## 5. `HANJI` 동적 투과율

이 게임의 시그니처 기능이다.

- 피격 누적 → `opacity` 감소 → 광투과 증가
- 상태는 `materials`가 소유하고 `surface:opacity` 이벤트로 발행한다
  (`ARCHITECTURE.md` §3). `render`가 구독한다.
- **P2A에서는 이벤트 발행과 상태 관리까지만.** 시각적 산란 표현은 P3 소유다.
  현재는 회색 규율 하에서 불투명도 변화만 보이면 된다.
- 구멍 위치는 **결정적**이어야 한다. `core/rng.js` 시드 PRNG만 사용.
  `Math.random()` 1회 호출이 `hanji_pierced` 샷을 영구히 불안정하게 만든다.

`hanji_pierced`(샷 9)가 누적 피격을 반영하되 **2회 캡처가 비트 동일**해야 한다.

## 6. FX 금지 — P2B로 이월

이번 패스에서 **만들지 마라**:
- GPU 파티클, 스파크, 먼지, 파편
- 데칼(탄흔) — 논리적 피격 기록은 하되 렌더하지 마라
- 예광, 총구화염, 트랜지언트 라이트
- 화면 흔들림, 히트 플래시

허용되는 플레이스홀더: 피격 지점에 **단색 회색 마커 1개**, 프레임 종료 시 즉시 제거.
`ballistic:*` 이벤트는 규정대로 전부 발행하라. P2B가 그것을 구독한다.

## 7. 결정성

P2A는 상태를 가진 시스템(피격 누적, 탄자, 무기 상태)을 처음 도입한다.
베이스라인이 깨지기 시작하는 지점이다.

- 모든 시간은 `core/clock.js`. `performance.now()` 직접 호출 금지
- 모든 난수는 `core/rng.js` 시드 PRNG
- `resetState()`가 피격 누적, 탄자 풀, 무기 상태, `HANJI` opacity를 **완전히** 초기화
- `stepFrames()` 재진입 안전성 유지 (감사 A 발견 사항)
