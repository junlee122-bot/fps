# P2B-BRIEF — FX (파티클 · 데칼 · 예광 · 총구화염)

**전제:** P2A 종료 게이트 전부 통과. HEAD `1f3219a`.
**이 패스의 한 줄:** 관통이 이미 정확하다. 그것을 **결정적으로** 보이게 만든다.

**여전히 회색이다.** 색·톤매핑·조명 룩은 P3 소유다.

---

## 0. 위험 요약

P2B는 참조 레포에서 **베이스라인 재현성이 죽은 지점**이다.
파티클 수명과 데칼 버퍼가 샷 간에 새어 11샷 중 10샷이 런마다 달라졌다.

우리는 `baseline.mjs`가 샷마다 새 페이지를 열어 그 경로를 이미 막았다.
그러나 P2B는 **한 샷 안에서도 상태를 축적하는 시스템**을 처음 도입한다.
`resetState()`의 범위가 불완전하면 그 즉시 재현성을 잃는다.

**두 번째 위험은 프리웜이다.** §6을 먼저 읽어라.

## 2. FX는 표면이 결정한다

`ARCHITECTURE.md`가 규정한 대로 파편 종류는 표면 타입이 결정한다.
`surfaces.js`의 `fx` 필드 **15종 전부**에 대응하는 프로파일을 구현한다.

`CONTRACT-PATCH-003-B`가 확립한 조항이 여기서 처음 검증된다:

> 관측 불가능한 표면은 새 재료가 아니라 자유변수다.

`ROOF_SOIL`의 `soil_puff`가 `EARTH_WALL`의 `dust_burst`와 **실제로 다르게 보여야** 한다.
같아 보인다면 PATCH-003-A의 승인 근거가 사후적으로 무너진다.

### `tools/fxaudit.mjs` (신규)
1. 15종 표면 각각에 사격하고 방출된 파티클 파라미터를 수집
2. 프로파일 키가 15개 전부 등록되어 있고 **서로 구별되는지** 검사
   (입자 수, 초기 속도 분포, 수명, 크기, 중력 계수 중 **최소 2개 축**에서 상이)
3. `null` 또는 미등록 프로파일이 1개라도 있으면 exit 1
4. 두 표면의 프로파일이 모든 축에서 동일하면 exit 1 — 특히 `ROOF_SOIL` vs `EARTH_WALL`

**PATCH-003-B 원칙 적용:** `harnesstest` **케이스 11** 신규 — 인위로 두 프로파일을
동일하게 만든 입력에서 `fxaudit`이 반드시 exit 1.

## 3. 결정성 — 이 패스의 핵심

### 3-1. `resetState()` 범위 확장
아래를 **완전히** 초기화해야 한다. 하나라도 빠지면 재현성이 깨진다.

- 파티클 풀 (활성 입자, 프리리스트 순서, 방출 누적자)
- 데칼 버퍼 (아틀라스 슬롯, 사용 인덱스, 에빅션 큐)
- 예광 목록
- 트랜지언트 라이트 목록
- 카메라 반동 누적값, 화면 흔들림 위상
- 강체 임펄스로 이동한 물체의 위치·속도

`playtest`에 검증을 추가하라: 사격 후 `resetState()` → 전 상태가
사격 이전과 **바이트 단위로 동일**함을 확인.

### 3-2. 시간과 난수
- 파티클 수명·스폰 타이밍은 전부 `core/clock.js`
- 스폰 지터, 스파크 방향, 파편 회전, 데칼 회전각은 전부 `core/rng.js` 시드 PRNG
- **`Math.random()` 1회 호출이 11샷 전부를 무효화한다**

### 3-3. 데칼 에빅션 결정성
데칼 버퍼가 가득 찼을 때의 축출 순서는 **결정적**이어야 한다.
FIFO 또는 삽입 인덱스 기반. 벽시계 시각, 프레임 번호(부팅 시각 의존), 거리 정렬 금지.

### 3-4. 데칼 위치 — `stoppedAt` 순서 의존성

`computePenetration()`의 잔여는 층별 인수의 **곱이므로 가환**이지만,
2% 조기 정지가 루프 내부에 있어 **정지 층 인덱스는 순서에 의존한다.**

예: 층 A가 0.5로, 층 B가 0.01로 떨어뜨릴 때
`A→B`는 인덱스 1에서, `B→A`는 인덱스 0에서 정지한다. 잔여는 둘 다 0이다.

**데칼은 `path`의 마지막 항목이 가리키는 층의 진입면에 찍힌다.**
레이어 체인 구성 순서가 틀리면 탄흔이 벽 반대쪽에 나타난다.

> **`PATCH-001-B` 케이스 3 부활 (`CONTRACT-NOTES P2A-2` 대체):**
> 순서 의존성 테스트는 **잔여값이 아니라 `stoppedAt`을 대상으로 한다.**
> 총곱이 정지 임계 미만인 2층 체인을 정순·역순으로 통과시켜
> `stoppedAt`이 서로 다름을 검증하라.

## 4. 트랜지언트 라이트 — 소유권 분리

`HANJI` 투과율을 P2A/P3로 나눈 것과 동일한 방식이다.

- **P2B 소유:** `light:transient` 이벤트 발행, 라이트 프리미티브 생성·수명 관리,
  총구 위치·방향 계산, 렌더 파이프라인 배선
- **P3 소유:** 강도 곡선, 색온도, 감쇠 반경, 노출 상호작용, 산란

P2B는 회색·고정 강도로 둔다. **P3가 튜닝할 훅만 만들어라.**

`muzzle_interior`(샷 8)가 이번 패스에서 처음 의미를 갖는다.
발사 후 정확히 지정된 프레임에서 캡처되어야 하며, 2회 캡처가 비트 동일해야 한다.

## 5. 데칼

- `HANJI`는 데칼이 아니라 **구멍**이다. P2A의 동적 투과율 시스템과 연결하되
  파열 형상(찢김 전파)을 추가한다
- `DANCHEONG`·`LACQUER`는 `DECAL` 표면이므로 하부재 데칼 위에
  **박리 표현**이 얹힌다. 관통 계산에는 여전히 참여하지 않는다
- 데칼 예산: 동시 512개 상한. 초과 시 §3-3 결정적 에빅션

## 6. 프리웜 — **최우선**

15종 표면 × fx 프로파일이 각각 별도 셰이더 변형을 만든다.
각 표면을 **처음 맞히는 순간** 컴파일되면 참조 레포의 728~1236 ms 스톨이 재현되며,
플레이 중 15회로 분산되어 원인 추적이 더 어렵다.

> **`src/core/prewarm.js`에 15종 fx 변형, 데칼 변형, 예광, 총구화염을 전부 추가한다.**
> `profile.mjs`의 "플레이 중 셰이더 컴파일" 항목이 **0**을 유지해야 한다.

프로그램 수 예산은 P1.5의 ≤40에서 **≤90**으로 상향한다 (최종 상한 120 유지).
부팅 예산 4초는 유지한다 — 프리웜 확대로 부팅이 늘어나면 여기서 처음 압박이 온다.

## 7. 성능 — 신규 선행지표

파티클은 **필레이트 비용**이므로 기존 선행지표 4종(삼각형·드로우콜·프로그램·CPU)
어디에도 잡히지 않는다. 계측 공백을 닫는다.

### `overdraw_estimate` (신규, 환경 무관)
```
overdraw = Σ(활성 파티클 화면 투영 면적 + 데칼 면적) / 화면 픽셀 수
```
CPU에서 산출한다. GPU 타이밍에 의존하지 마라.

| 지표 | P2B 예산 | 최종 상한 |
|---|---|---|
| `overdraw_estimate` p95 | ≤ 2.5 | 4.0 |
| 동시 활성 파티클 | ≤ 4,000 | 8,000 |
| 동시 데칼 | ≤ 512 | 512 |
| 프로그램 수 | ≤ 90 | 120 |

측정은 **최악 시나리오**로 한다: 실내에서 산탄 연사 + 기와 파편 낙하 동시 발생.

## 8. 카메라 반동 · 강체 피격

- **카메라 반동:** 스프링 기반. `player`가 아니라 `weapons`가 소유하고
  카메라에 오프셋을 발행한다. 반동 누적은 `resetState()` 범위에 포함
- **강체 임펄스:** 탄자가 강체에 잔여 에너지 비례 임펄스를 전달.
  `ballistic:hit`의 `incidentEnergy`를 사용
- **기와 낙하:** `ROOF_TILE` 피격 시 기와장이 물리 객체로 분리·낙하
  (`ARCHITECTURE.md` §2 명시 사항). 낙하 기와는 `resetState()` 범위
