# P1.5-BRIEF — 지오메트리 보강 (단기 패스)

**전제:** P1 종료 조건 6종 통과. 커밋 `adb841c`.
**사유:** P1이 삼각형 예산의 5.6%만 사용한 채 종료됐고, 보고된 한계 2건이
모두 지오메트리 밀도 부족을 가리킨다. P3에서 이 부족이 드러나면
`materials` 오너가 `world`를 열어야 하며, 이는 순차 단일 오너 규칙 위반이다.

**이 패스의 한 줄:** 건물을 늘리지 말고, 있는 건물의 부재 밀도를 올린다.
**여전히 회색이다.**

---

## 0. 계약 정정 — 삼각형 지표 정의

### 문제
`P1-BRIEF` §0-3의 선행지표 "삼각형 ≤ 2,000,000"이 어느 수치를 뜻하는지
명시되지 않았다. `renderer.info.render.triangles`는 **프레임당 컬링 후 가시**
삼각형이며, 씬 전체 복잡도가 아니다.

가시 삼각형만 게이트하면 카메라가 마당 중앙을 볼 때는 통과하고,
P3에서 지붕 위·원경 샷으로 시야가 열릴 때 예산이 붕괴한다.
게이트가 지켜야 할 대상은 후자다.

### 정정 (`P1-BRIEF` §0-3 표 및 `HARNESS.md` §6에 반영)

`profile.mjs`는 **두 수치를 분리 출력하고 각각 게이트한다.**

| 지표 | 정의 | P1.5 예산 | 최종 상한 |
|---|---|---|---|
| `tris_scene` | 씬 전체 삼각형 (인스턴스 전개 후, 컬링 무관) | **≤ 600,000** | 6,000,000 |
| `tris_frame_p95` | 프레임당 가시 삼각형 p95 (11샷 순회 기준) | ≤ 250,000 | 2,000,000 |

`tris_scene`은 씬그래프 순회로 산출한다. 렌더러 통계를 쓰지 마라.
`InstancedMesh`는 `count × 지오메트리 삼각형`으로 전개해 합산한다.

`tris_frame_p95`는 11샷 전체를 순회하며 측정한다.
단일 카메라 측정은 무효다 — 이것이 이번 정정의 핵심이다.

## 1. 범위 — 정확히 두 가지

### 1-1. 공포(栱包) 밀도 확보 **[우선]**

현재 간이형. `dancheong_closeup`(샷 4)이 프레임에 담는 주 피사체이며,
`ARCHITECTURE.md`가 이 샷을 "머티리얼 최악 케이스"로 지정한 이유가
여기에 부재 밀도가 있어야 단청 문양이 얹힐 면이 생기기 때문이다.

최소 요구 부재:

| 부재 | 요구 |
|---|---|
| 주두(柱頭) | 굽 곡면 표현 |
| 소로(小累) | 개별 메시. 뭉뚱그리지 말 것 |
| 첨차(檐遮) | 하단 곡선(연화두형) 표현 |
| 살미(山彌) | 쇠서 돌출 |
| 행공첨차 | 다포에만 |
| 장혀·도리 | 결구 관계가 보이도록 |

- **주심포 1동 / 다포 2동 대비를 유지한다.** 다포는 주간포를 실제 간격으로 배치.
- 출목 수를 건물별로 다르게 해서 실루엣 차이를 만든다 (예: 2출목 / 3출목).
- 전 부재 표면 타입은 `WOOD_COLUMN`. 두께표 준수.

### 1-2. 팔작지붕 도입

현재 전 건물 맞배. 관아 주요 건물(동헌·객사)은 팔작이 일반적이며,
지붕 실루엣이 전부 동일하면 `roofline_distant`(샷 5)가 판별력을 잃는다.

- **동헌·객사 2동을 팔작으로 전환.** 나머지는 맞배 유지 (대비가 목적).
- 합각면, 추녀, 사래, 선자연 구성.
- 기와 30 mm + 보토 80 mm 2레이어 구조를 곡면에서도 유지 — **관통 체인이 깨지면 안 된다.**
- 처마 곡선(앙곡·안허리)을 넣는다. 직선 처마는 한옥 실루엣의 핵심을 버리는 것이다.

### 1-3. 그 외 전부 금지

- 건물 추가 금지 (3 + 2 유지)
- 색·텍스처·노멀맵·PBR 조정 금지. **회색 3단계 규율 유지**
- 조명 변경 금지
- P2 선행 작업 금지 (무기·탄도·FX 손대지 말 것)
- 레벨 레이아웃 변경 금지 — P0 앵커(기단 전면 z=-18, 담장 ±44) 및
  `coveraudit` 0.12% 상태를 보존한다

## 2. 확정 해석 승인

`CONTRACT-NOTES P1-1`의 해석을 **정식 승인한다.** 재논의하지 마라.

> 회색 규율은 알베도·러프니스·메탈니스에 적용된다.
> **반투과(`translucent`)와 자발광은 표면 타입의 물리적 정체성이므로 P0 값으로 동결하며,
> 회색화 대상이 아니다.** `HANJI`가 불투명해지면 그것은 더 이상 `HANJI`가 아니다.

P3의 `materials` 오너는 이 두 속성의 **값을 조정할 수 있으나**,
`surfaces.js`의 `translucent` / `dynamicOpacity` 플래그 자체는 변경할 수 없다.

## 3. 하네스 회귀 테스트 (신규 요구)

`--tolerance`가 값 없이 1로 새는 게이트 약화 결함이 **재발**했다.
같은 자리에서 두 번 발생한 결함 클래스는 세 번째가 있다.

`tools/harnesstest.mjs`를 추가한다. **하네스가 하네스를 검증한다.**

최소 케이스:

1. `imagediff` — 인위적으로 1픽셀 변경한 이미지 쌍에 대해 **반드시 exit 1**
2. `imagediff` — `--tolerance` 플래그를 값 없이 전달했을 때 **0으로 처리되거나 에러**.
   1로 새면 실패
3. `profile` — 인자 없이 실행 시 duration 30 / runs 3 / dpr 2가 적용됨
4. `profile` — 축소 인자 사용 시 `NON-CONTRACT MEASUREMENT` 배너 출력
5. `baseline` — 동일 커밋 2회 실행이 바이트 동일
6. `surfaceaudit` — 표면 미매핑 메시를 인위 주입했을 때 exit 1
7. `coveraudit` — 위반율이 임계 초과하도록 조작한 입력에 대해 exit 1
8. p95 산출 — 알려진 분포에 대해 정답과 일치 (다중 run 합산 포함)

`harnesstest.mjs`는 이후 **모든 패스의 종료 조건에 영구 포함된다.**

## 4. 샷 재조준

지오메트리가 바뀌므로 아래 2샷의 카메라를 갱신한다. 나머지 9샷은 건드리지 마라.

- `dancheong_closeup` — 다포 공포 출목 구조가 프레임 60% 이상을 채우도록
- `roofline_distant` — 팔작 2동과 맞배 3동의 실루엣 차이가 한 프레임에 보이도록

갱신 사유를 `tools/shots.js` 주석에 기록한다.

| 항목 | 시점 | 내용 |
|---|---|---|
| `coveraudit` ↔ 내비메시 정합 | **P4** | 현재 통행 그래프는 셀 근사다. P4에서 실제 내비메시가 생기면 `coveraudit`을 내비메시 기반으로 재실행한다. 근사와 내비메시가 불일치하면 "AI는 도달 못 하는데 감사는 통과"가 발생한다 |

## 6. 종료 조건

```bash
node tools/harnesstest.mjs         # 신규 — exit 0
node tools/surfaceaudit.mjs        # 미매핑 0건
node tools/coveraudit.mjs          # 위반 ≤ 2% (0.12% 수준 유지 확인)
node tools/baseline.mjs --out current/
node tools/imagediff.mjs baseline/ current/    # 의도 변경 확인 후 baseline 갱신
node tools/profile.mjs             # tris_scene ≤ 600k, tris_frame_p95 ≤ 250k, 그 외 예산 유지
node tools/playtest.mjs            # exit 0
```

추가:
- **P2 관통 레이어 체인이 팔작지붕에서도 성립함을 확인.**
  기와 → 보토 → 서까래가 곡면 지붕과 합각면 양쪽에서 유지되어야 한다.
- 사용자가 Apple Silicon에서 `profile.mjs` 1회 실측 → 기록
