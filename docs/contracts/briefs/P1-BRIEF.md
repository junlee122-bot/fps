# P1-BRIEF — 월드 (한옥 모듈 킷 + 레벨)

**전제:** P0 종료 조건 3종 통과 확인. `p0-baseline` 태그 생성 완료.
**선행 문서:** `ARCHITECTURE.md`, `HARNESS.md`, `CONTRACT-PATCH-001.md`
**이 패스의 한 줄:** 지오메트리와 표면 매핑만. **색을 칠하지 마라.**

## 0. 착수 전 선결 조건

아래 3건을 먼저 완료하고 보고하라. 완료 전 월드 코드를 쓰지 마라.

### 0-1. CONTRACT-PATCH-001 적용
4개 패치 전부 적용 후 `baseline` → `imagediff` 재실행.
`identical:true`가 나와야 한다. 순수 신규 export이므로 픽셀이 변하면 안 된다.

### 0-2. 감사 재실행 — **순차 2개만**
P0에서 감사 에이전트 10개 중 8개가 세션 한도로 미완주했다.
이는 프롬프트 §4.1이 경고한 병렬 팬아웃 실패 패턴을 감사 계층에서 재현한 것이다.

**10개 병렬을 다시 시도하지 마라.** 커버리지 공백이 남은 두 렌즈만
**순차로, 한 번에 하나씩** 실행한다.

| 감사 | 범위 |
|---|---|
| A. 결정성 | 단일 시간 소스 위반, `Math.random()` 직접 호출, 미시드 PRNG, 캡처 간 상태 누수 |
| B. 하네스 수치 | 툴 기본값 vs 계약 조건 일치, 히치 귀속 정확성, imagediff tolerance 0 유지, 통계 산출 로직 |

각 감사는 발견 항목 수와 수정 후 재검증 결과를 보고한다.

### 0-3. 성능 선행지표 게이트 도입
SwiftShader 환경에서 절대 fps는 판정 무효다. 이 공백을 방치하면
P3 아트 패스에서 지오메트리가 폭증한 뒤에야 발견된다.
*(참조 레포 실측: 아트 패스가 5.9M → 11.3M로 3배 증가, 최적화가 절반만 회수)*

`profile.mjs`에 **환경 무관 선행지표**를 추가하고 패스별 예산으로 게이트한다.

| 선행지표 | P1 예산 | 최종 상한 |
|---|---|---|
| 삼각형 | **≤ 2,000,000** | 6,000,000 |
| 드로우콜 | ≤ 900 | 1,500 |
| 고유 셰이더 프로그램 | ≤ 40 | 120 |
| CPU 프레임 시간 (GPU 제외) | ≤ 6 ms p95 | 8 ms p95 |

`profile.mjs`는 GPU 의존 수치와 환경 무관 수치를 **출력에서 분리**하고,
소프트웨어 렌더러 감지 시 fps 섹션에 `GPU-INVALID` 배너를 출력한다.

P1 종료 시 이 4개 선행지표로 게이트한다. 절대 fps는 사용자가
Apple Silicon에서 별도 실측한다.

## 1. 범위

**단일 맵: 관아 또는 사찰 경내, 약 90 × 90 m.**
`ARCHITECTURE.md` §5 공간 문법을 구현한다.

건물 수는 **주 건물 3동 + 부속 2동 + 회랑 + 담장**으로 제한한다.
더 짓지 마라. 2M 삼각형 예산은 생각보다 빨리 소진된다.

## 2. 모듈 킷 — 두께가 게임플레이다

**관통 계산이 실제 두께에 의존한다.** 모든 부재는 아래 두께를 실측값으로 갖는다.
장식적으로 얇게 만들지 마라. `computePenetration()`의 입력이다.

| 부재 | 표면 타입 | 두께/치수 | 비고 |
|---|---|---|---|
| 기단 | `GRANITE` | 높이 600 mm, 두께 900 mm | **주 엄폐물** |
| 초석 | `GRANITE` | ø 600 mm | 엄폐 가능 |
| 기둥 | `WOOD_COLUMN` | ø 300 mm, 배흘림 | 관통됨. 신뢰 불가 |
| 창방·평방 | `WOOD_COLUMN` | 180 × 300 mm | |
| 공포 | `WOOD_COLUMN` | 부재별 | 주심포 1동, 다포 2동으로 대비 |
| 도리·서까래 | `WOOD_COLUMN` | ø 150 mm | |
| 지붕 기와 | `ROOF_TILE` | 30 mm + 보토 80 mm | 2레이어로 모델링 |
| 창호지 | `HANJI` | 0.3 mm | |
| 창살 | `WOOD_LATTICE` | 24 mm | 창호지와 별개 레이어 |
| 심벽(흙벽) | `EARTH_WALL` | 100 mm | |
| 판벽·판문 | `WOOD_PLANK` | 45 mm | |
| 우물마루 | `WOOD_PLANK` | 40 mm | **누각에서 아래로 관통 가능해야 함** |
| 담장 하부 | `GRANITE` | 900 mm | 엄폐 |
| 담장 상부 | `ROOF_TILE` | 30 mm | 관통 |
| 마당 | `PACKED_DIRT` | — | 지면. 엄폐 후보 아님 |
| 범종 | `BRONZE` | — | **맵 전체 3개 이하** |

### 레이어 구성 필수 사례
탄환 한 발이 아래를 순서대로 통과할 수 있어야 한다. 이것이 P2 관통 테스트의 대상이다.

```
창호지(0.3) → 창살(24) → [실내 공간] → 창살(24) → 창호지(0.3)
기와(30) → 보토(80) → 서까래(150) → [실내]
담장상부 기와(30) → [관통]  /  담장하부 화강암(900) → [차단]
```

## 3. 회색 규율

- 모든 부재는 **동일한 회색 `MeshStandardMaterial`** 하나를 공유한다.
- 색상, 단청, 텍스처, 노멀맵, PBR 파라미터 조정 **전부 금지.**
- 조명은 P0의 기본 설정을 유지한다. 건드리지 마라.
- 이유: 형태와 색을 동시에 판단하면 둘 다 틀린다. P3가 색을 소유한다.

**예외 없음.** "구조가 잘 안 보여서 색을 조금만"은 P3 침범이다.
가독성이 필요하면 회색 명도만 3단계까지 허용한다.

## 4. 신규 하네스 툴 2종

### `tools/surfaceaudit.mjs` (PATCH-001-D 요구)
월드 씬그래프 전수 순회. 표면 타입이 매핑되지 않은 메시가 1개라도 있으면 exit 1.
미매핑 노드의 이름·경로·바운딩박스를 출력한다.
**기본 표면이 없으므로 이 툴이 유일한 안전망이다.**

### `tools/coveraudit.mjs`
`ARCHITECTURE.md` §5 레벨 규칙의 자동 검증:

> 플레이어가 서 있는 어떤 지점에서도, 관통 불가 엄폐물까지 2초 이동 이내

구현:
1. 플레이어 이동 가능 영역을 1 m 그리드로 샘플링
2. 각 샘플에서 `VERTICAL_COVER_SURFACES` 표면까지 최단 **경로** 거리 계산
   (직선 거리 아님 — 벽을 뚫고 갈 수 없다)
3. 플레이어 최대 속도 기준 2초 초과 지점을 히트맵 PNG로 출력
4. 위반 샘플이 전체의 **2%를 초과하면 exit 1**

위반 지점은 레벨 수정으로 해결한다. 임계값을 올려서 해결하지 마라.

## 5. 추가 요구

- **내비메시 대비:** P4에서 AI가 들어온다. 축퇴 삼각형, 겹친 바닥면,
  0.4 m 미만 틈새를 만들지 마라. 지금 만들면 P4에서 월드를 다시 손대야 한다.
- **인스턴싱:** 기와, 서까래, 창살, 공포 부재는 반복이 극심하다.
  `InstancedMesh`로 처리하지 않으면 드로우콜 예산이 즉시 터진다.
- **결정성:** 절차적 배치는 전부 `core/rng.js` 시드 PRNG를 쓴다.
  `Math.random()` 1회 호출이 baseline 전체를 무효화한다.
- **신규 샷 없음:** 11샷 정의는 그대로 둔다. 카메라 위치가 실제 지오메트리에
  맞도록 `tools/shots.js`의 좌표만 갱신하고, 갱신 사유를 기록하라.

## 6. 종료 조건

아래 **전부** 통과해야 P2 지시를 요청할 수 있다.

```bash
node tools/surfaceaudit.mjs        # exit 0 — 미매핑 0건
node tools/coveraudit.mjs          # exit 0 — 위반 ≤ 2%
node tools/baseline.mjs --out current/
node tools/imagediff.mjs baseline/ current/   # 의도 변경 확인 후 baseline 갱신
node tools/profile.mjs             # 선행지표 4종 P1 예산 이내
node tools/playtest.mjs            # exit 0
```

추가로:
- 사용자가 Apple Silicon에서 `profile.mjs` 1회 실측 → fps 수치 기록 (게이트 아님, 기록용)
- 삼각형 2M 초과 시 **건물을 줄인다.** 예산을 올리지 마라.
