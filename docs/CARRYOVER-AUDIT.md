# 이월 누락 소급 감사 (CONTRACT-PATCH-011-B) — 2026-09-19

**1차 출처 확보 (2026-09-19 갱신)**: 초판은 브리프 원문이 리포에 없어 **받는 쪽 코드 주석**을 증거로 썼다. 발주자가 계약 번들을 전달해
`docs/contracts/`(브리프 P1–P3 · 패치 001–011 · 마스터 프롬프트 · 원문 3종)가 리포에 들어왔으므로, **"받는 쪽 브리프에 명시?" 열을 원문으로
재검증했다.** 초판의 판정은 전부 유지됐고, 근거가 추정에서 인용으로 바뀌었다. 판정 기준은 그대로다 — "처리됨"은 **화면·코드에서 확인되는 상태**이고,
계획·훅만 있고 값이 회색·고정이면 미처리다.

## 받는 쪽 원문 (P3-BRIEF)

§3 체크포인트 표는 **C1 렌더 · C2 하늘 · C3 머티리얼 15종 · C4 톤매핑**뿐이고, §10 「이월 항목 정리」는 네 줄 — 박리 데칼 배치 / 낙하 기와 픽셀
게이트 / 3중 공면 / Apple Silicon 실측 — 이다. **P2B 가 넘긴 네 항목은 한 줄도 없다.** 전문 검색에서 `파티클`은 overdraw 절(§8)에만 나오고,
그 문장은 지시가 아니라 **가정**이다:

> §8 — "P2B 실측 0.003 은 회색 규율 하의 빈약한 FX 에서 나온 수치이며 **시험된 값이 아니다.** P3 에서 파티클 크기·불투명도·발광, 볼류메트릭 안개,
> 창호지 반투과가 **들어오면** …"

즉 계약 작성자는 FX 룩이 P3 에서 들어올 것을 **알고 있었고**, 그것을 overdraw 예산의 근거로 썼으면서, **작업 항목으로는 적지 않았다.**
`예광`·`화염`·`색온도`는 P3-BRIEF 전문에 **한 번도** 나오지 않는다.

## 결과

**확인된 이월 14건 중 미처리 6건(#1–#6) + 미해결 1건(#10).** 미처리 6건은 **전부 P2B → P3 구간이고, 전부 받는 쪽 브리프에 없다.**
반대로 받는 쪽에 적힌 이월(#7·#8·#11·#12·#13)은 **전부 처리됐다.** #10 만 예외인데, 적혔고 처리되지 않은 이유는 지시 누락이 아니라
**환경 제약**(컨테이너 GPU 없음)이며 패치로 개정돼 발주자 실행 대기 중이다.

> **상관관계가 완전하다 — 받는 쪽 브리프에 적힌 이월은 처리됐고, 적히지 않은 이월은 하나도 처리되지 않았다.**
> 넘기는 쪽에만 적은 이월은 사라진다는 011-B 의 진단이 원문으로 확인된다.

미처리 6건에 노출 등급(011-A)을 부여해 R4 작업 목록에 등재한다.

## 영구 규칙 (011-B 조치 2, P4-BRIEF 부터 적용)

> **이월 항목은 받는 쪽 브리프에 반드시 명시한다.** 계약 작성자는 새 브리프를 쓸 때 직전 패스들의 이월 목록을 먼저 대조하고,
> 에이전트는 새 브리프를 받으면 직전 이월 목록과 대조해 **누락을 보고한다.**

원문 보관 규칙도 함께 선다 — 새 브리프·패치는 **수령 즉시 `docs/contracts/` 에 커밋한다**(번들 README). 이 감사가 코드 주석에
의존해야 했던 원인이 원문 부재였다.

### P4-BRIEF 수령 시 절차 (발주자 지시 2026-09-19)

1. `docs/contracts/briefs/P4-BRIEF.md` 로 **즉시 커밋**.
2. **첫 작업: 계약 모순·모호 지점 스캔**(원 프롬프트 §9 의 규칙을 이후 브리프에도 적용) → 발견 즉시 보고 → 그 다음에 구현 착수.
